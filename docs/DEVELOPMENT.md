# Для разработчиков

Сборка, выпуск релизов, устройство пакетов и что именно проверено. Для пользователя достаточно [README](../README.md).

## Что внутри

| Каталог | Пакет | Содержимое |
|---|---|---|
| `zapret2/` | `zapret2` | Makefile (скачивает и собирает upstream), procd-init, генератор конфига из UCI и пресета, 10 встроенных пресетов, hotplug, cron-обновление, фоновые задачи |
| `luci-app-zapret2/` | `luci-app-zapret2`, `luci-i18n-zapret2-ru` | страницы LuCI (Состояние, Пресеты, Списки, Настройки, Подбор стратегии, Диагностика), общий модуль SVG-иконок, rpcd-плагин на ucode (в том числе проверка обновлений на GitHub), ACL, русский перевод |
| `build.sh` | — | сборка пакетов на официальном SDK OpenWrt (нативно на Linux или в Docker) |

Версия zapret2 закреплена в [zapret2/Makefile](../zapret2/Makefile) (`PKG_VERSION`/`PKG_HASH`): сейчас **1.0.7**.

## Релизы и автосборка

Пакеты для роутеров собирает GitHub Actions, вручную собирать их не нужно. Роутеры ставят всегда **последний релиз**
командой из README (`install.sh`).

**Как выпустить версию**

1. Поднимите `PKG_VERSION` в [luci-app-zapret2/Makefile](../luci-app-zapret2/Makefile) (например, `2.1.0`) и
   закоммитьте: проверка обновлений в LuCI сравнивает именно эту версию с тегом релиза.
2. Поставьте тег и отправьте его: `git tag v2.1.0 && git push origin v2.1.0`.
3. Дальше автоматически ([release.yml](../.github/workflows/release.yml)): проверки → сборка → публикация релиза.
   Следить можно на вкладке *Actions*; через 20–40 минут релиз появится на странице *Releases* и станет «последним».

Если тег не совпадает с `PKG_VERSION`, сборка остановится с понятной ошибкой до начала долгих шагов. Тег вида
`v2.1.0-rc1` публикуется как пре-релиз и «последним» не становится.

**Что делает workflow**

| Шаг | Что происходит |
|---|---|
| `checks` ([ci.yml](../.github/workflows/ci.yml)) | страницы LuCI после JSMin, перевод, синтаксис скриптов, JSON — те же проверки идут на каждый push и pull request |
| `prepare` | проверяет формат тега и его совпадение с `PKG_VERSION` |
| `build` | 18 заданий: 9 платформ × OpenWrt 24.10 (`.ipk`) и 25.12 (`.apk`); каждое запускает `./build.sh` на официальном SDK; патч-версии берутся актуальные (`oldstable`/`stable` из `.versions.json`) |
| `release` | собирает файлы, считает `SHA256SUMS`, кладёт `install.sh`, создаёт релиз (описание — из коммитов с прошлого тега) |

Платформы выбраны по одной на архитектуру пакетов:

| Платформа (target) | Архитектура пакетов | Примеры устройств |
|---|---|---|
| `x86/64` | `x86_64` | ПК, виртуальные машины |
| `mediatek/filogic` | `aarch64_cortex-a53` | Xiaomi AX3000T, Cudy, Routerich и другие на MT798x |
| `ramips/mt7621` | `mipsel_24kc` | Keenetic/Xiaomi 4A Gigabit и другие на MT7621 |
| `ath79/generic` | `mips_24kc` | TP-Link и другие на Atheros |
| `ipq40xx/generic` | `arm_cortex-a7_neon-vfpv4` | GL.iNet B1300, Zyxel NBG6617 |
| `mvebu/cortexa9` | `arm_cortex-a9_vfpv3-d16` | Linksys WRT1900/3200 |
| `bcm27xx/bcm2711` | `aarch64_cortex-a72` | Raspberry Pi 4 |
| `rockchip/armv8` | `aarch64_generic` | NanoPi, Radxa |
| `ipq806x/generic` | `arm_cortex-a15_neon-vfpv4` | Netgear R7800 |

Чтобы добавить платформу, допишите строку в `matrix.include` в `release.yml` (`target` и `id` — как на
downloads.openwrt.org). Архитектуру пакетов workflow берёт из самого SDK, поэтому ошибиться в имени файла нельзя.
Пакеты `luci-*` не зависят от архитектуры и берутся из одного задания (`x86/64`) на каждую версию OpenWrt.

**Файлы релиза**

* `zapret2_<версия>_<архитектура>.ipk` и `zapret2-<версия>_<архитектура>.apk` — пакет с `nfqws2` под архитектуру;
* `luci-app-zapret2_…_all` и `luci-i18n-zapret2-ru_…_all` — интерфейс и русский перевод (`.ipk` и `.apk`);
* `SHA256SUMS` — контрольные суммы всех файлов; `install.sh` — установщик.

**install.sh** ([install.sh](../install.sh)) запускается на роутере и использует только стабильные адреса
`releases/latest/download/…` (API GitHub и его лимиты не нужны): определяет архитектуру (`DISTRIB_ARCH`) и менеджер
пакетов (`opkg` → `.ipk`, `apk` → `.apk`), скачивает `SHA256SUMS`, выбирает файлы под архитектуру, проверяет суммы и
ставит пакеты. Пакеты `.ipk` собраны под OpenWrt 24.10, `.apk` — под 25.12: на другой версии скрипт отказывается
работать без `ZAPRET_FORCE=1`. Переменные: `ZAPRET_FORCE`, `ZAPRET_NO_RU`, `ZAPRET_NO_INSTALL` (только скачать и
проверить), `ZAPRET_REPO`, `ZAPRET_BASE_URL`.

**Вручную.** *Actions → Release → Run workflow*: без тега только соберёт пакеты (их можно скачать из артефактов запуска),
с тегом ещё и опубликует релиз.

**Требования к репозиторию.** Он должен быть **публичным**: роутеры скачивают релизы и проверяют обновления без
авторизации, для приватного репозитория GitHub отвечает «не найден». Токен доступа в проекте намеренно не используется.

## Ручная сборка

Нужны Linux или Docker. На macOS — только Docker (`--docker`).

```sh
./build.sh --target mediatek/filogic --openwrt 24.10.7   # свой роутер: платформа и версия с самого роутера
./build.sh                                              # x86/64, последний stable OpenWrt
./build.sh --docker --target ramips/mt7621              # внутри Docker (macOS, любой Linux без зависимостей)
./build.sh --zapret-version latest                      # свежий релиз zapret2 (не проверялся этим портом)
```

Что делает скрипт: определяет версию OpenWrt → скачивает SDK и проверяет sha256 → кладёт в SDK пакеты из
репозитория → подключает feeds `base`, `packages`, `luci` → `make package/zapret2/compile
package/luci-app-zapret2/compile`. Во время компиляции OpenWrt скачивает tarball zapret2 с
`codeload.github.com/bol-van/zapret2` и сверяет хэш. Готовые пакеты — в `out/`: `.ipk` (OpenWrt ≤ 24.10) или `.apk`
(OpenWrt ≥ 25.12). Скачанный SDK кэшируется в `.build/`.

Свою платформу и версию смотрите на роутере: `cat /etc/openwrt_release` (`DISTRIB_TARGET`, `DISTRIB_RELEASE`).
Собирайте под ту же версию OpenWrt, что стоит на роутере.

> **Mac на Apple Silicon.** SDK OpenWrt — x86_64-программа. В Docker на ARM она запускается через эмуляцию, и в
> эмуляции QEMU, на которой проверялся порт (Colima по умолчанию), кросс-компилятор SDK падает с сегфолтом. Используйте
> Docker Desktop или OrbStack (Rosetta), Colima с `--vm-type vz --vz-rosetta` (диск не меньше 40 ГБ), либо собирайте
> на x86_64 Linux / в CI. Образ сборки при первом запуске собирается 5–15 минут.

Без `build.sh`: добавьте этот репозиторий как feed в обычное дерево OpenWrt
(`src-link zapret2 /путь/к/openwrt-zapret`), затем `./scripts/feeds update zapret2 &&
./scripts/feeds install -a -p zapret2` и выберите пакеты в `make menuconfig`
(*Network → Firewall → zapret2*, *LuCI → Applications → luci-app-zapret2*).

## Как это устроено

* **Источник настроек — UCI** (`/etc/config/zapret2`, секция `main`) и файл выбранного пресета. Родные скрипты zapret2
  читают shell-файл `config`, поэтому `/usr/libexec/zapret2/env.sh` генерирует `/etc/zapret2/config`:
  `config.default` из upstream + значения из UCI + `NFQWS2_OPT`/порты из пресета + `extra_config`. Файл пересоздаётся
  автоматически при изменении UCI или пресетов; руками его не правьте.
* Опции UCI называются как переменные upstream в нижнем регистре (`nfqws2_enable` → `NFQWS2_ENABLE`, `mode_filter` →
  `MODE_FILTER`). Любую переменную, для которой нет поля в LuCI, можно задать через `extra_config`.
* **Файрвол и демон** — родная логика upstream (`init.d/openwrt/functions`, `common/*`); init-скрипт — адаптация
  upstream-овского `init.d/openwrt/zapret2`. Правила nftables: таблица `inet zapret2`, очередь NFQUEUE 300.
* **Каталоги.** `/usr/share/zapret2` — скрипты, Lua, встроенные пресеты (только чтение), `/usr/bin/nfqws2` и `/usr/libexec/zapret2` — бинарники,
  `/etc/zapret2` — конфиг, списки, свои и скачанные пресеты. Пользовательские данные сохраняются при sysupgrade
  (`/lib/upgrade/keep.d/zapret2`).
* **Флаг `enabled`** определяет запуск при загрузке и реакцию на «Сохранить и применить». Кнопка «Включить» на странице
  *Состояние* ставит `enabled=1` и `nfqws2_enable=1` и запускает службу, «Выключить» — снимает `enabled` и останавливает её.
* **Смена режима** на странице *Списки* записывает `mode_filter` и, если служба запущена, перезапускает `nfqws2`;
  сохранение списка отправляет `nfqws2` сигнал перечитать файл (без перезапуска). Скачанные и сохранённые списки
  имеют права `0644`: `nfqws2` работает от пользователя `daemon` и перечитывает их сам.
* **LuCI** общается с роутером через ubus-объект `luci.zapret2` (rpcd-плагин на ucode); пользовательский ввод проверяется по
  белым спискам и не попадает в командные строки. Все строки, пришедшие из сети (названия пресетов, URL, логи), выводятся
  в интерфейсе как текст, а не как HTML.

## Проверка обновлений

Кнопка «Проверить обновления» на странице *Состояние* спрашивает GitHub, есть ли новая версия **этого пакета**
(`luci-app-zapret2`), и показывает версию, ссылку на релиз и описание изменений (как текст, не как HTML).
Ничего не скачивается и не устанавливается само: кнопка только сообщает и показывает команду обновления
(`install.sh`, см. выше), которую вы запускаете на роутере сами.

* Проверяется репозиторий проекта `FlamesC0der/openwrt-zapret`: он задан в коде, выбора репозитория и токена доступа в
  интерфейсе нет. Запросы идут без авторизации, поэтому репозиторий должен быть публичным (для приватного ответ
  «не найден»), а у GitHub есть лимит анонимных запросов (60 в час с одного адреса).
* Сначала запрашивается `releases/latest` (публикуйте релиз с `.ipk`/`.apk` во вложениях), если релизов нет — берётся
  самый большой тег (номера сравниваются как числа: `v2.10.0` новее `v2.9.0`). Тег должен быть вида `v2.1.0` или
  `2.1.0` и сравниваться с версией пакета `PKG_VERSION` из [luci-app-zapret2/Makefile](../luci-app-zapret2/Makefile):
  при выпуске новой версии поднимите её там и поставьте такой же тег.
* *Настройки → Обновления → Проверять обновления каждый день* добавляет проверку в ежедневное задание (час — в
  *Настройки → Списки*); результат пишется в системный журнал (`logread -e zapret2-update`). Автоустановки нет.
* Ошибки объясняются понятными сообщениями: лимит запросов или отказ (401/403), репозиторий или релизы не найдены
  (404), нет сети. Если раньше вы вводили токен или меняли репозиторий, при установке пакета эти опции
  (`github_token`, `github_repo`, `github_api`) удаляются из `/etc/config/zapret2`.

## Диагностика TCP 16-20: как это работает

Страница *Диагностика* повторяет проверку проекта [dpi-checkers](https://github.com/hyperion-cs/dpi-checkers)
([TCP 16-20](https://hyperion-cs.github.io/dpi-checkers/ru/tcp-16-20/), описание метода —
[net4people/bbs#490](https://github.com/net4people/bbs/issues/490)). Некоторые провайдеры обрывают TCP-соединение с
зарубежными хостингами и CDN, когда клиент отправил 16–20 КБ данных: сайты открываются наполовину, загрузки зависают.
Для каждого хоста из списка проекта роутер (curl):

1. проверяет, что хост отвечает (`HEAD`; таймаут — «нет», другая ошибка — «неизвестно»);
2. отправляет 64 КиБ случайных данных одним `POST`: если соединение зависло, обрыв **обнаружен**;
3. иначе — десять `HEAD`-запросов с адресом по 7 КБ в одном соединении (те же 64 КиБ): зависание — обрыв обнаружен,
   ошибка без зависания — «возможно» (хост жив) или «маловероятно» (хост не подтвердил, что жив);
4. найденный обрыв проверяется **ещё раз**: настоящий DPI режет соединение каждый раз, а случайный таймаут
   (перегруженный сервер, лимит запросов) бывает разовым, поэтому если повтор прошёл, результат понижается до «возможно».

Список хостов скачивается при каждом запуске со страницы проекта; если она недоступна, берётся встроенный снимок
([zapret2/files/diag-suite.json](../zapret2/files/diag-suite.json), 36 хостов; данные проекта dpi-checkers, Apache-2.0).
Можно проверить и **свой хост** (только DNS-имя). Проверка идёт с роутера, поэтому её трафик проходит через правила
zapret2 так же, как трафик устройств: запустите её при включённом и выключенном zapret2 или отметьте «Проверить ещё и
при остановленном zapret2» (служба остановится на время второго прохода и запустится снова) — таблица покажет оба
результата рядом. Чтобы показать провайдера, у публичного сервиса RIPE Stat запрашивается автономная система адреса
роутера; больше ничего, кроме самих хостов проверки, не запрашивается. Результаты хранятся в `/var/run/zapret2-diag/`
(пропадают при перезагрузке). Из консоли: `/usr/libexec/zapret2/job.sh run diagnose [HOST=имя] [TIMEOUT=15] [COMPARE=1]`.

## Совместимость

* Готовые пакеты из релиза: OpenWrt **24.10** (`.ipk`) и **25.12** (`.apk`), 9 архитектур (таблица выше). Для других
  версий (например, 23.05) и платформ соберите пакеты сами: `./build.sh`.
* Нужны `rpcd-mod-ucode` и LuCI на JS. Основной режим — **nftables / fw4**.
* Нужен `luajit` — он есть для всех распространённых архитектур OpenWrt (arm, aarch64, mips, mipsel, x86, powerpc, riscv64).
* Режим iptables + fw3 (OpenWrt 21.02 и старше) перенесён из upstream, но **не проверялся**.
* Нужны ядро и пакеты с NFQUEUE (`kmod-nft-queue`); о flow offloading см. опцию «Flow offloading».

## Инструменты разработчика

`tools/check-js.sh` — проверка страниц LuCI до сборки: собирает тот же JSMin, который `luci.mk` запускает при сборке пакета,
минифицирует каждый файл и проверяет синтаксис результата. Это важно: минификатор ломает некоторые конструкции
(например, регулярное выражение с кавычками внутри), и страница на роутере тогда падает с `SyntaxError`, хотя исходник
в порядке. Нужны `node`, `cc`, `curl`. Проверяет и общий модуль иконок `resources/zapret2/icons.js`.

`tools/po-sync.py` — сверка строк интерфейса (`_('...')` в JS и заголовки меню) с русским переводом: показывает
непереведённые, устаревшие строки и несовпадающие подстановки (`%s`/`%d`); с флагом `--write` пересобирает
`po/templates/zapret2.pot` и `po/ru/zapret2.po`, сохраняя готовые переводы. Исходные тексты интерфейса английские,
русский идёт через перевод; код выходит с ошибкой, пока есть непереведённые строки.

**Иконки.** Все значки рисуются встроенным SVG из `resources/zapret2/icons.js` (24×24, линейные, цвет берётся из цвета
текста, поэтому подходят к светлой и тёмной темам); чтобы добавить значок, допишите его разметку в таблицу `ICONS`.
Тема LuCI закрашивает любой `<svg>`, лежащий прямо в `<div style>`, сплошным фоном, поэтому у значков стоит inline
`background:transparent !important`.

## Обновление zapret2

1. `./build.sh --zapret-version <версия>` — соберёт указанный релиз, либо
2. поправьте `PKG_VERSION` и `PKG_HASH` в [zapret2/Makefile](../zapret2/Makefile)
   (`curl -L https://codeload.github.com/bol-van/zapret2/tar.gz/v<версия> | sha256sum`).

После обновления сверьтесь с `docs/changes.txt` upstream: порт использует `init.d/openwrt/functions`, `config.default`
и Lua-библиотеки оригинала, а init-скрипт повторяет логику `init.d/openwrt/zapret2`; zapret2 развивается быстро.

## Что проверено, а что нет

Проверено:

* Бинарники `nfqws2`, `mdig`, `ip2net` компилируются теми же флагами на musl (Alpine) и запускаются.
* Все пресеты: `nfqws2 --dry-run` (синтаксис параметров и наличие файлов), существование всех используемых Lua-функций,
  выполнение на живом HTTP/HTTPS/UDP-трафике без ошибок Lua.
* Генерация конфига, init-скрипт (запуск/остановка/reload/загрузка с `enabled=0|1`), таблица nftables, cron, фоновые
  задачи, скачивание пресетов и списков по URL — в контейнере с настоящим OpenWrt (procd, ubus, rpcd, busybox ash, nft).
* rpcd-плагин под настоящими `ucode` и `rpcd`; все пять страниц LuCI в Chrome (минифицированные тем же JSMin, что и
  при сборке) без ошибок JS, включая переключение пресетов, копирование и удаление своих, редактирование и поиск в
  списках, добавление списка с URL, экранирование «вредоносного» скачанного пресета, включение одной кнопкой, смену
  режима, быстрое добавление сайтов в оба списка (адрес нормализуется, дубликаты и мусор отклоняются).
* Реальная командная строка `nfqws2` после смены режима: `--hostlist` и `--hostlist-exclude` в режимах со списками,
  только `--hostlist-exclude` в режиме «Всё».
* Пресет `general-alt` на настоящем OpenWrt в контейнере: объявленные списки создаются и скачиваются с настоящего

  с фейками и `fakedsplit`, неизвестный TCP — в ветку «unknown», UDP на порт 5000 получает 12 фейков на каждую из первых
  двух датаграмм (третья идёт без изменений), STUN на порт 50000 переключается на профиль Discord, DNS (порт 53) и TLS
  на порту 443 вне списков не затрагиваются; в логе нет ошибок Lua.

* Диагностика TCP 16-20 на настоящем OpenWrt в контейнере, через интерфейс и напрямую: список хостов скачивается с сайта
  проекта, полный проход по 36 хостам занимает около минуты; провайдер определяется по RIPE Stat. Имитация DPI

  работающем zapret2, остановка, второй проход, запуск обратно; остановка задачи посреди второго прохода тоже
  возвращает службу, процессов curl и временных файлов не остаётся. Враждебный список хостов (IP-адреса, пробелы, `;`,
  порт, запись без `host`, управляющие символы) отбрасывается или очищается, команды из него не выполняются; свой хост и
  таймаут проверяются и в плагине, и в скрипте.

**Не проверено:**

* Полная кросс-компиляция `nfqws2` на SDK: компилятор SDK (x86_64) не запустился под эмуляцией на машине, где
  проводилась проверка (сегфолт `aarch64-openwrt-linux-musl-gcc`), поэтому при проверке упаковки шаг компиляции
  был заменён заглушкой. Те же команды компиляции проверены на musl в Alpine. Если `./build.sh` на вашей машине
  упадёт — пришлите последние строки вывода.
* **Сам запуск GitHub Actions** (`release.yml`): на GitHub он здесь не выполнялся. Проверены его части (скрипты, YAML,
  `build.sh` на SDK 24.10.7), но первые сборки по тегу могут выявить мелочи (например, недостающий пакет в runner'е
  или другие имена файлов `.apk` в SDK 25.12) — смотрите вкладку *Actions*; упавшие задания можно перезапустить.
* Установка настоящих пакетов из релиза менеджерами `opkg` и `apk`: на устройстве нет `apk mkpkg`, поэтому вызовы
  менеджеров проверялись заглушками. Файлы `.apk` в релизе названы с архитектурой, а перед установкой установщик
  возвращает им обычные имена, как в SDK.

  результаты на вашем провайдере стоит сверить с [оригинальной проверкой](https://hyperion-cs.github.io/dpi-checkers/ru/tcp-16-20/)

  репозитории сейчас; пресет проверен на версии списков от ноября 2026.
